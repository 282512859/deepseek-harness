# Feature: task-log (Claude Code tasks mirror)

Date: 2026-08-16
Status: implemented (new package, additive)

## What

A scope-only row mirroring Claude Code's `.claude/tasks` into the
harness-native shape: one JSON file per task under the sandbox workspace,
with `task_start` / `task_update` / `task_list` / `task_show` tools and a
prompt section that keeps long-running work visible across turns.

## Decisions worth keeping

1. **The fs seam, never raw paths.** Every read/write/list goes through
   `ctx.fs`, so the mounted sandbox policy fences task files exactly like
   `tool-fs`.
2. **Strict task ids before any file access.** `validateTaskId` allows only
   `[a-z0-9][a-z0-9-]{0,63}`; the file name derives from the validated id, so
   traversal and absolute paths are structurally impossible.
3. **Notes are append-only within a record.** `task_update` either changes
   the validated status enum or appends a trimmed note (or both); an empty
   update is rejected. Records stay small and parseable.
4. **`task_list` tolerates foreign and corrupt files.** The journal directory
   may hold user files; entries that fail `parseTaskRecord` are skipped rather
   than failing the list.
5. **Ids are time-derived** (`task-<unix-ms>`), deterministic for tests and
   unique per call for a single agent.

## Deferred

- Real-composition boot test is still owed per the product-visible-plugin
  policy; unit coverage is 100% on all four metrics.
- `task_list` rescans the directory on every call; no index is kept.
- The OpenClaw comparison-list heartbeat item maps to the existing
  `@deepseek-ai/dsh-schedule` (durable session-log reminders), not a new
  package; DeepClaw integration mounts that row instead.
